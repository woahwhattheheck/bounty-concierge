## Host oracle

`bias_gelu_oracle.py` computes only the accurate erf-based reference:

`GELU(x) = 0.5 * x * (1 + erf(x / sqrt(2)))`

The issue's four observed legacy device outputs are stored as evidence constants and are **not** regenerated by a fabricated hardware approximation. The issue table displays `x` to four decimals, so its paired reference values are treated as rounded evidence; evaluating the displayed decimal itself is only required to agree within `5e-5`, not bit-for-bit. The separate standard tanh GELU function is explicitly labeled a mathematical contrast, because the issue's legacy device result at `x=-3.0059` is exactly `0` while standard tanh GELU is not.
