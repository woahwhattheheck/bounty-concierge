## Finding

`memanto memory sync` crosses a security boundary by taking recalled memory and writing it into coding-agent instruction surfaces such as `CLAUDE.md`, Copilot instructions and skill files.

Before the repair, dynamic sync:
1. recalled active records of type `instruction`, `preference` or `goal`;
2. required confidence >= 0.8 and semantic similarity;
3. **did not gate on provenance**;
4. formatted every returned record's content verbatim;
5. passed that text to `inject_dynamic_memories`, which replaces the Memanto dynamic section inside the connected agent's instruction files.

Therefore a lower-trust `imported`, `inferred`, `observed`, or legacy/missing-provenance record could be promoted into durable prompt/instruction text. The next coding-agent session then consumes that memory as an instruction. This matches #1852's explicit indirect-prompt-injection threat category.

No live backend exploitation, production credential, tenant data, destructive request, or secret was needed to establish the path.

## Deterministic reproduction

1. Store or import an active memory with:
   - type: `instruction`, `preference`, or `goal`
   - confidence >= 0.8
   - non-authoritative provenance such as `imported`
   - instruction-like content
2. Run `memanto memory sync` for a connected coding agent.
3. On the vulnerable base, observe the memory content copied into the dynamic section of the connected instruction file.
4. Start the coding agent: the memory now occupies an instruction/prompt surface rather than a normal recall/data surface.

## Repair

The owner-fork head adds a fail-closed trust gate in `memanto/cli/commands/memory_mgmt.py`:

```python
TRUSTED_DYNAMIC_PROVENANCE = frozenset(
    {"explicit_statement", "corrected", "validated"}
)
```

Only those provenance values may cross into dynamic instruction sync. Imported, inferred, observed and missing-provenance memories remain available through ordinary recall; they are not deleted, hidden, or reclassified. The CLI also reports skipped-untrusted counts.

Regression coverage in `tests/test_dynamic_memory_injection.py` proves:
- malicious `imported` instruction payload is rejected;
- malicious `inferred` goal payload is rejected;
- `explicit_statement` preference is retained;
- `validated` instruction is retained;
- missing provenance fails closed.
